# 机器人消息与简报

本文是消息内容、展示、存储、投递和下一阶段优化的主要手册。当前里程碑见 [README](../README.md)，生产版本与进程操作见[部署手册](deployment.md)。

## 当前实现（2026-09-06 已发布）

用户最新明确：图片是快捷播报，第一句说清事情是什么，有帮助时再附一句已有历史/背景。此前“完整详情全部进入图片”的要求已被此决定替代。“牛长婷”仍向一个显式用户发送一条普通 Markdown，依次包含所有图页和一个详情链接；没有互动卡片模板或卡片搭建器依赖。

| 部分 | 当前实现 |
| --- | --- |
| 聊天图页 | 宽 `720`、单页最高 `1280` 的 SVG；按 `core`、`support`、`muted` 排序，同组保持原顺序；全部条目进入图片 |
| 信息层级 | 事件句 `30px`、可选背景 `22px`、时间/来源 `18px`；栏目标题 `20px`、页脚 `16px`，视觉重量集中在事件句 |
| 信息分组 | 自定义 SVG 模板直接排版；每条事件、背景、时间同属一个浅灰绿色信息块，块内附加间距 `2–4px`、上下内边距 `12px`、块间留白 `16px`；不画分隔线 |
| 扫读强调 | 单一灰绿色系；每条最多轻量强调事件句里的两个已有带单位数值，背景弱化；不把普通数字匹配宣称为语义上的核心提取 |
| 背景选择 | 只读取已有 `[历史：…]`、`【历史：…】` 或历史/背景标签，取首个完整句；无标记时省略，不从实体清单编写历史 |
| 详情信息 | 图片移除网址、详细正文和实体清单；完整快照与 H5 继续保留这些内容，图谱深度探索不在本轮范围内 |
| 分页 | 尽量保持单条快讯完整；过长既有事件句换行/续页，不按字数截断或缩字号冒充简洁；每图显示页码 |
| 详情 H5 | 常驻目录与当前详情，移动端目录收窄但保留；全部条目可访问 |
| 图片与详情关系 | 共用同一份持久化快照和 ID；图片快速告知事件，H5 提供完整内容，详情页本轮保持原样 |
| 访问 | 新消息图片为 `/briefings/<id>/image.svg?v=quick-2&page=<页码>`；不带页码的既有路径仍返回所有图页，无账号密码 |

尺寸和排版仍待实际钉钉呈现验收。L1/L2/L3+ 保留级别文字和排序，不使用多色区分等级。数值与单位尽量同一行，图内不画按钮、嵌套卡片边框或重复零计数；真实详情链接位于图外。图片 URL 带布局版本以区分旧缓存，ETag 同时区分版本和页码。

设计参考 [NN/g 的标题扫读研究](https://www.nngroup.com/articles/layer-cake-pattern-scanning/)与[可扫读文本建议](https://www.nngroup.com/articles/how-users-read-on-the-web/)：明确事件句、有限度强调。将这些网页研究应用于聊天图片是本轮设计选择，具体字号和颜色仍以用户反馈为准。

现有 AI 总结提示词要求以主体、动作和关键变化组成一个事件句，并保留“拟、预计、据称、尚未”等限定。没有增加 AI 调用或改写已保存的快照；渲染直接使用已有事件句，不能把排版测试当作所有生成内容都已合格。历史关联沿用现有总结链路，不在图片请求时新查图谱或生成背景。

## 数据与投递契约

```text
新闻 / AI 总结
  → BriefingDraft（完整条目）
  → 校验并持久化 BriefingDocument
  → 图片 URL + H5 URL
  → 钉钉机器人单聊
```

`BriefingDraft` 包含标题、时间/数量元信息、L1/L2/L3+ 计数和 `items`。每个条目包含 ID、级别、色调、目录标签、标题、时间、完整详情、来源和原文 URL；类型只在格式化文件中定义，校验在 store 中维护。

标识是规范化 draft 的 SHA-256 前 32 个十六进制字符（128 位）。相同内容重试复用同一快照；文件保存在 `BRIEFING_STORAGE_PATH/<id>.json`，先写临时文件再原子重命名。合法 ID 必须匹配 `[a-f0-9]{32}`，不能用任意路径读取文件。

投递必须同时满足通知启用、凭据齐全、一个合法收件人、HTTPS Origin 合法，以及运行时公网 Host 与 Web 构建值一致。载荷的 `userIds` 只有一项；不允许群聊、`atAll`、部门、隐式用户或广播 fallback。

钉钉返回 `processQueryKey` 且没有无效/限流收件人时，当前代码认为接口接受。**接口接受不等于用户已阅读或图片渲染成功**，后者要用客户端验收。发送失败不能把 Level 1 新闻记为已发送。

## 配置与公开边界

配置键：

- `ENABLE_DINGTALK_NOTIFICATION`：代码/模板默认关闭；生产开启状态见发布快照。公共配置同时支持 `WEB_ENABLE_DINGTALK_NOTIFICATION` 覆盖，排查时核对有效值，不只看单个键。
- `DINGTALK_APP_CLIENT_ID`、`DINGTALK_APP_CLIENT_SECRET`：只在运行环境配置。
- `DINGTALK_TARGET_USER_ID`：一个明确用户 ID，空值、逗号列表或空白分隔列表都失败；不写入文档。
- `BRIEFING_PUBLIC_BASE_URL`：当前为 `https://drudge.microzj.com`；必须是无凭据、路径、查询参数和锚点的 HTTPS Origin。
- `BRIEFING_STORAGE_PATH`：Web 可持续读写的绝对目录，属于生产数据，不提交或清理。

完整安全模板在 [env.example](../env.example)。修改公网域名需同步根配置并重建 Web；不要手工修改构建产物。`DINGTALK_CARD_TEMPLATE_ID` 已不再使用。

简报与工作台当前都公开可读，128 位 ID 不是身份认证；转发链接仍可访问。不能把密钥、私人正文或敏感系统告警放入公开简报。工作台保留浏览器跨站操作校验，但不能据此声称直接调用者经过认证。

## 验证方法

1. 本地使用合成内容，覆盖事件句、可选短背景、实际总结中的内联历史/时间格式、混合级别、十条内容、超长既有事件句、缺失来源/时间与转义；验证限定词保留、详情清单不入图、快照不变、数值与单位换行、全部事件进入同一消息和分页路由。测试位于 Web 的 `tests/services/` 与 `tests/apis/briefing-image.test.ts`，沿用禁网保护。
2. 真实浏览器检查桌面/手机视口、图片可读性、目录切换、完整信息、Console 与失败请求。模拟数据结果单独标明。
3. 生产只读确认同一快照的 H5 和 SVG 都能免登录访问。工作台和 `GET /api/scan` 状态接口应正常，不再预期旧 Host 限制的 404。
4. 需要真实钉钉展示验收时，明确测试内容、次数和收件人，使用已有授权；分别记录接口结果和用户反馈。

以下命令会真实发送一条标为模拟数据的消息，**不用于普通只读检查**。仅在测试投递已获授权、配置齐全时运行：

```bash
ENABLE_DINGTALK_NOTIFICATION=true \
DRUDGE_BRIEFING_PUBLIC_HOST=drudge.microzj.com \
pnpm briefing:test-live
```

它不触发真实新闻扫描，目标仍只来自显式单收件人配置。首次启用通知时先在关闭状态完成本地和公网验证，再做授权测试；验收后按部署手册启用并重启 Web 与调度器。该流程不表示当前生产通知仍关闭。

`/briefings/health` 只返回固定存活文本，不验证存储或钉钉。通知 service 的 `healthCheck()` 会校验配置并获取 access token，但也不会发送消息；两者都不能代替实际展示验收。

## 停用与回退

按已有授权把有效通知配置关闭，再按部署手册重启 `web-app` 与 `web-scheduler`。不要通过清空收件人制造半配置状态。展示版本回退须同时保持应用、域名与入口一致，不回退到隐式群发。

快照当前不自动删除。制定保留期前先确认历史链接有效期；回退不能删除已发送简报或消费位点。
