# 机器人消息与简报

本文是消息内容、展示、存储、投递和下一阶段优化的主要手册。当前里程碑见 [README](../README.md)，生产版本与进程操作见[部署手册](deployment.md)。

## 当前线上实现（2026-09-06 已发布）

生产已发布 `plain-2`。用户最新明确停止设计发散，图片收敛为普通文字列表：一句事件，有帮助时再附一句已有历史/背景，字体尽量小。线上布局版本为 `plain-2`，在小字模板中仅对核心动作/变化加一点颜色和字重。此前“完整详情全部进入图片”的要求已被此决定替代。“牛长婷”仍向一个显式用户发送一条普通 Markdown，依次包含所有图页和一个详情链接；没有互动卡片模板或卡片搭建器依赖。

| 部分           | 当前实现                                                                                                                                             |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 聊天图页       | 逻辑宽 `720`、单页最高 `1280`，服务端按双倍像素输出 PNG；按 `core`、`support`、`muted` 排序，同组保持原顺序；全部条目进入图片                                               |
| 字号           | 事件句 `18px`、行高 `26px`；可选历史/背景 `16px`、行高 `23px`，普通字重                                                                              |
| 排版           | 白底黑灰文字，四周 `20px` 留白；事件与背景连续排放，条目间距 `10px`；没有色块、边框、分隔线或侧栏                                                    |
| 显示范围       | 只显示事件和可选背景；移除可见栏目名、等级、时间/来源、品牌页脚；仅对显式标记的核心动作/变化使用灰绿色 `#537568` 和 `600` 字重，历史保持灰色普通字重 |
| 背景选择       | 只读取已有 `[历史：…]`、`【历史：…】` 或历史/背景标签，取首个完整句；无标记时省略，不从实体清单编写历史                                              |
| 详情信息       | 图片移除网址、详细正文和实体清单；完整快照与 H5 继续保留这些内容，图谱深度探索不在本轮范围内                                                         |
| 分页           | 尽量保持单条快讯完整；过长既有事件句换行/续页，不截断，不随条数继续缩字；仅多图显示 `14px` 页码，单条跨页时保留小字“接上图”                          |
| 详情 H5        | 常驻目录与当前详情，移动端目录收窄但保留；全部条目可访问                                                                                             |
| 图片与详情关系 | 共用同一份持久化快照和 ID；图片快速告知事件，H5 提供完整内容，详情页本轮保持原样                                                                     |
| 访问           | 新消息图片为 `/briefings/<id>/image.png?v=plain-2&page=<页码>`；PNG 默认第 1 页，SVG 旧路径继续可读，无账号密码                                         |

模板仍使用 SVG 组织文字，服务端通过 `@resvg/resvg-js@2.6.2` 转成 PNG 后供钉钉加载。Markdown 只承载 PNG 图片和图外详情链接。已有尾部时间仅在与条目元数据匹配时从图中移除，事件本身的其他日期保持；快照和 H5 内容不变。数值与单位尽量同一行，图内不画操作入口。图片 URL 带布局版本以区分旧缓存，PNG 的 ETag 同时区分布局版本、格式和页码。

PNG 使用随应用携带的 Noto Sans SC Regular / Bold 字体（来源和许可见 `packages/web-app/assets/fonts/`），不依赖系统字体；postbuild 将字体复制到 standalone。缺少字体时明确失败，避免生成空白成功响应。最终图片为 `1440px` 宽、最高 `2560px`，提高小字清晰度，逻辑字号和布局未放大。既有 `image.svg` 保持原格式，不带页码时仍返回全部图页；已发送消息的 URL 和钉钉缓存不会因本次改动自动替换。

现有 AI 总结提示词要求以主体、动作和关键变化组成一个事件句，并保留“拟、预计、据称、尚未”等限定。现在只用 Markdown 加粗标记通常一个、最多两个核心动作/变化短语，相关确定性限定需一起标记；不再要求所有公司名和数字都加粗，也不生成 Emoji 或 HTML 颜色标签。没有增加 AI 调用或改写已保存的快照；渲染直接使用已有事件句，不能把排版测试当作所有生成内容都已合格。历史关联沿用现有总结链路，不在图片请求时新查图谱或生成背景。

## 数据与投递契约

```text
新闻 / AI 总结
  → BriefingDraft（完整条目）
  → 校验并持久化 BriefingDocument
  → 图片 URL + H5 URL
  → 钉钉机器人单聊
```

`BriefingDraft` 包含标题、时间/数量元信息、L1/L2/L3+ 计数和 `items`。每个条目包含 ID、级别、色调、目录标签、标题、时间、完整详情、来源和原文 URL。可选 `emphasis` 最多保存两个标题中已有的字面短语，来自原始标题的 Markdown 加粗标记；store 校验短语属于标题。字段缺失时不推断重点、不新增默认值，因此既有快照继续可读。图片只强调清理后仍属于事件句的部分，换行后继续保留标记；H5 的纯文字标题不变。类型只在格式化文件中定义，校验在 store 中维护。

标识是规范化 draft 的 SHA-256 前 32 个十六进制字符（128 位）。相同内容重试复用同一快照；文件保存在 `BRIEFING_STORAGE_PATH/<id>.json`，先写临时文件再原子重命名。合法 ID 必须匹配 `[a-f0-9]{32}`，不能用任意路径读取文件。

投递必须同时满足通知启用、凭据齐全、一个合法收件人、HTTPS Origin 合法，以及运行时公网 Host 与 Web 构建值一致。载荷的 `userIds` 只有一项；不允许群聊、`atAll`、部门、隐式用户或广播 fallback。

钉钉返回 `processQueryKey` 且没有无效/限流收件人时，当前代码认为接口接受。**接口接受不等于用户已阅读或图片渲染成功**，后者要用客户端验收。发送失败不能把 Level 1 新闻记为已发送。

## 配置与公开边界

配置键：

- `ENABLE_DINGTALK_NOTIFICATION`：代码/模板默认关闭；生产开启状态见发布快照。公共配置同时支持 `WEB_ENABLE_DINGTALK_NOTIFICATION` 覆盖，排查时核对有效值，不只看单个键。
- `DINGTALK_APP_CLIENT_ID`、`DINGTALK_APP_CLIENT_SECRET`：只在运行环境配置。
- `DINGTALK_TARGET_USER_ID`：一个明确用户 ID，空值、逗号列表或空白分隔列表都失败；不写入文档。
- `BRIEFING_PUBLIC_BASE_URL`：当前为 `https://drudge.microzj.com`；必须是无凭据、路径、查询参数和锚点的 HTTPS Origin。
- `BRIEFING_STORAGE_PATH`：Web 可持续读写的绝对目录，属于生产数据，不提交或清理。

完整安全模板在 [env.example](../env.example)。修改公网域名需同步根配置并重建 Web；不要手工修改构建产物。`DINGTALK_CARD_TEMPLATE_ID` 已不再使用。

简报与工作台当前都公开可读，128 位 ID 不是身份认证；转发链接仍可访问。不能把密钥、私人正文或敏感系统告警放入公开简报。工作台保留浏览器跨站操作校验，但不能据此声称直接调用者经过认证。

## 验证方法

1. 本地使用合成内容，覆盖事件句、可选短背景、实际总结中的内联历史/时间格式、混合级别、十条内容、超长既有事件句、缺失来源/时间与转义；验证限定词保留、详情清单不入图、快照不变、数值与单位换行、全部事件进入同一消息和分页路由。测试位于 Web 的 `tests/services/` 与 `tests/apis/briefing-image.test.ts`、`tests/apis/briefing-png.test.ts`，沿用禁网保护。PNG 测试使用真实渲染库，验证文件签名、尺寸、中文不同字形、重点样式和每页内容对应。
2. 真实浏览器检查桌面/手机视口、图片可读性、目录切换、完整信息、Console 与失败请求。模拟数据结果单独标明。
3. 生产只读确认同一快照的 H5、PNG 和旧 SVG 都能免登录访问；PNG 必须是实际 PNG 字节和 `image/png`，并核对 standalone 字体和渲染库已打包。工作台和 `GET /api/scan` 状态接口应正常，不再预期旧 Host 限制的 404。
4. 需要真实钉钉展示验收时，明确测试内容、次数和收件人，使用已有授权；分别记录接口结果和用户反馈。

以下命令会真实发送一条标为模拟数据的消息，**不用于普通只读检查**。仅在测试投递已获授权、配置齐全时运行：

```bash
ENABLE_DINGTALK_NOTIFICATION=true \
DRUDGE_BRIEFING_PUBLIC_HOST=drudge.microzj.com \
pnpm briefing:test-live
```

它不触发真实新闻扫描，目标仍只来自显式单收件人配置。首次启用通知时先在关闭状态完成本地和公网验证，再做授权测试；验收后按部署手册启用并重启 Web 与调度器。该流程不表示当前生产通知仍关闭。

`/briefings/health` 只返回固定存活文本，不验证存储或钉钉。通知 service 的 `healthCheck()` 会校验配置并获取 access token，但也不会发送消息；两者都不能代替实际展示验收。

## 停用与回退

按已有授权把有效通知配置关闭，再按部署手册重启 `web-app` 与 `web-scheduler`。不要通过清空收件人制造半配置状态。展示版本回退须同时保持应用、域名与入口一致，不回退到隐式群发。

快照当前不自动删除。制定保留期前先确认历史链接有效期；回退不能删除已发送简报或消费位点。
