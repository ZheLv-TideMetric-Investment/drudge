# 简报与工作台统一域名并直接访问

决定日期：2026-09-05。状态：已发布生效，用户已确认里程碑完成。版本与现场证据见[发布快照](../deployment.md#最近发布快照)。

## 原因

简报、图片和工作台本来由同一个 Web App 提供。用户要求统一使用 `drudge.microzj.com`、去掉 `news.microzj.com`，随后明确要求先移除工作台的账号密码认证。

## 有效决定

- Home Ingress 只声明一个 `public/none` Web component，全部业务仍在 Tide；101 只转发。
- 工作台页面、业务 API、简报和图片均直接访问，不使用 Basic Auth、公开路径豁免或代理认证标记。
- 保留浏览器跨站操作检查；它不构成身份认证，扫描、AI 总结和推送接口也可被直接调用。
- 钉钉 API 凭据、通知开关与显式收件人规则不变。其他应用已有 owner 认证能力不受影响。

## 备选与兼容

两个子域名、同域名下仅工作台认证的方案都已被用户最终选择替代，不作为待完成事项。

首页提供工作台，简报继续使用 `/briefings/<id>` 与 `/briefings/<id>/image.svg`。旧 news 入口不保留别名或跳转；旧消息里的旧域名链接失效，原 ID 可在新域名访问。

应用构建域名、运行消息配置和路由已同步。后续变更或回退需保持三者一致，具体命令只维护在[部署手册](../deployment.md)，不新增端口、登录服务或密码存储。
