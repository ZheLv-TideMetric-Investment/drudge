# 简报与工作台统一域名

2026-09-05，用户明确要求两个入口统一使用 `drudge.microzj.com`，不保留 `news.microzj.com`；随后明确要求先去掉工作台的账号密码认证。本记录对应本地实现，生产发布状态需以发布验收为准。

简报、图片和工作台本来就在 Tide 的同一个 Web App。统一域名后，首页为工作台，`/briefings/<id>` 和 `/briefings/<id>/image.svg` 保留原路径与数据。采集和图处理仍是独立 worker，不对外新增入口。

使用 Home Ingress 原有 `public/none` 转发，工作台、简报和图片均直接访问。删除这次为工作台新增的 Basic Auth 配置、公开路径豁免及代理认证标记；应用不再按公网 Host 限制业务路由。其他应用已有的 owner 认证能力不变，不新增登录服务、密码存储或端口。

曾考虑两个子域名，以及同域名下仅工作台要求认证的方案；用户最终选择统一域名且先不加认证。扫描、AI 总结和推送接口随工作台开放。保留浏览器跨站操作检查，但它不构成身份认证。钉钉 API 自身的凭据和单收件人投递规则不受此决定影响。

发布时同步入口、简报 URL 配置、构建和应用进程，无需配置 owner 账号。回滚时恢复对应的应用、域名配置和入口版本。旧消息中的旧域名 URL 不再可用，原简报 ID 可在新域名访问。具体命令与验收只维护在[发布手册](../deployment.md#12-工作台入口)。
