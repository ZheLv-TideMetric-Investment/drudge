# 图片摘要与 H5 完整详情

决定日期：2026-09-03。初版已实施，用户已确认测试消息图片与详情正常。2026-09-05 曾要求完整内容分图；2026-09-06 用户进一步明确目标是快速播报，将其收拢为“事件句 + 可选短背景”，并授权发布紧凑分组版 `quick-2`。公网访问边界由[统一域名决定](2026-09-05-unified-drudge-domain.md)替代；当前展示、源码与验收见[消息手册](../dingtalk-briefing.md)。

## 原因

长 Markdown 让所有信息权重接近；互动卡片受搭建器布局和模板/代码双端契约限制，仍占据过多聊天空间。用户要求首屏紧凑，同时保留完整信息、目录和详情切换。

## 有效决定

- 消息使用普通单聊 Markdown，包含依次排列的快讯图页和详情入口；每条事件进入消息，不设置三条上限。
- 第一句独立说清事件，用字重和克制颜色强调；有现成历史或背景时，补一句。机构清单、完整正文、图谱深度探索属于详情和后续层次，不以全量信息填满快讯。
- 图片采用小幅字号层次与柔和单一色系，移除原文网址等操作性内容，保留事件的确定性限定、时间与来源名称。
- 完整简报先持久化，H5 保留全部事实、主体、时间、来源和原文链接；目录常驻，切换当前详情。
- 样式、业务格式、存储和传输分层；不再依赖钉钉卡片模板。
- 沿用显式单收件人规则，不增加群聊或广播路径。

## 备选与兼容

继续长 Markdown 简单但层级弱；继续互动卡片增加布局约束和模板维护；运行时 PNG 需要额外光栅化与中文字体能力。当前使用 SVG，后续是否改变以实际客户端效果和需求决定，不预先增加运行服务。

`DINGTALK_CARD_TEMPLATE_ID` 已退出代码。原业务通知调用和失败语义保持；完整快照与已发链接不能在展示迭代中当缓存删除。

生产基线、后续迭代与验收范围以消息手册区分，不能把本地预览或公网 HTTP 成功当作钉钉客户端验收。回退使用对应应用与配置版本，不恢复默认群发；操作与验收只按主要手册执行。
