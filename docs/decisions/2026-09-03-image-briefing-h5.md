# 主动推送采用图片摘要与 H5 详情

## 背景

原有长 Markdown 在聊天窗口中让所有信息接近同一权重；随后尝试的钉钉互动卡片仍然体积过大，受搭建器布局和变量渲染限制，难以得到紧凑、稳定的信息层级。用户要求首屏控制在一屏或半屏，同时保留基本信息量，并保留目录与详情的渐进披露交互。

## 决定

- 钉钉消息改为一张固定比例图片摘要和一个 H5 完整详情链接。
- 图片突出最高权重一条，再展示两条次要信息；更多条目只显示数量提示。
- 完整简报先持久化，H5 展示全部条目，左侧目录常驻、右侧详情切换。
- 机器人使用普通单聊 Markdown，不再依赖钉钉互动卡片模板。
- 继续执行一个显式收件人的 fail-closed 规则，不增加群聊或广播路径。
- 当时公网简报 Host 仅放行简报与静态资源；此访问边界已由用户 2026-09-05 的[统一域名与免登录决定](2026-09-05-unified-drudge-domain.md)替代。

## 不做什么

- 不新增数据库、对象存储、队列、截图浏览器或卡片模板同步服务。
- 不在图片中塞入全部正文，也不为视觉紧凑删除 H5 中的事实与来源。
- 不在本次增加登录、收件人管理后台或多人投递。
- 本决定不授权发送消息、提交、部署、入口安装或生产重启。

## 备选方案

- 继续使用长 Markdown：实现最简单，但无法建立足够强的视觉权重。
- 继续优化互动卡片：可以交互，但搭建器约束与模板/代码双端契约增加维护成本，且实际效果仍偏大。
- 运行时生成 PNG：客户端兼容性更确定，但需要可靠的中文字体和光栅化依赖；当前 PVE 不具备该运行条件。

## 迁移与兼容

- 删除 `DINGTALK_CARD_TEMPLATE_ID` 配置和互动卡片发送代码。
- 原业务通知方法与扫描成功语义不变；内部改为“保存简报后发送链接”。
- 旧钉钉模板不再被代码引用，可在新链路稳定后由独立操作决定是否下线。
- 2026-09-01 显式收件人决定继续有效；其中“互动卡片”和“禁止转发”的实现描述由本决定取代。

## 验证

- 单元测试覆盖完整条目保留、快照读写、SVG 转义与优先级、HTTPS 地址、单收件人载荷和失败路径。
- Next 构建验证 H5 与 SVG 路由。
- 使用本地快照在真实浏览器检查桌面和手机视口、目录切换、Console 与请求。
- 部署后另做一次经授权的钉钉真实消息验收。

## 回滚

先关闭 `ENABLE_DINGTALK_NOTIFICATION`，再按发布手册回滚到上一稳定提交并恢复其配置。任何回滚都不得恢复默认群发或隐式收件人。
