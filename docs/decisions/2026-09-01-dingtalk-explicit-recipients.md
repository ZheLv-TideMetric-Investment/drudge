# 钉钉主动推送使用显式收件人

> 后续修订：2026-09-03 起，展示与传输改为“图片摘要 + H5 详情”的普通单聊 Markdown，见[对应决定](2026-09-03-image-briefing-h5.md)。本文的显式单收件人、默认关闭和禁止广播原则继续有效；互动卡片模板与禁止转发的实现描述不再适用。

## 背景

Drudge 原先通过群 Webhook 主动推送长 Markdown。群本身隐含了接收范围，既不适合控制“谁能收到”，也无法实现目录与详情并存的紧凑交互。用户决定复用现有企业机器人“牛长婷”，同时要求未来可以更换或增加收件人，但绝不能默认向所有人发送。

## 决定

- Web App 主动推送使用企业机器人单聊。
- 通知默认关闭，且必须配置一个明确的 `DINGTALK_TARGET_USER_ID` 才允许投递。
- 第一版只支持一个可配置用户；用户身份不写死为仓库所有者本人。
- 投递载荷只允许明确用户的机器人单聊，禁止群空间、`atAll` 和广播 fallback。
- 只有钉钉明确返回投递成功，扫描任务才把本批新闻记为已发送。
- 未来多人支持只能采用显式白名单和逐人结果，不得恢复默认群发。

## 不做什么

- 不建设收件人管理后台、角色系统或通用消息平台。
- 不保留 Web App 群 Webhook 作为备用发送路径。
- 本决定不改变两个 worker 独立的异常告警 Webhook。
- 本决定不授权实际发送测试消息、提交、部署或重启生产。

## 迁移

1. 保留现有机器人并确认单聊消息权限。
2. 在运行环境配置应用凭证和唯一收件人 userId。
3. 先在通知关闭状态完成静态验证，再经明确确认向指定用户做一次实际投递。
4. 验收通过后启用生产通知；旧 Web App 群 Webhook 实现和测试随代码变更删除。

## 回滚

立即将 `ENABLE_DINGTALK_NOTIFICATION=false` 并重启 Web 相关进程，即可停止所有主动推送。展示故障按当前展示决定回滚；不回退到隐式群发。
